# 命中链忽略的理论依据

本文整理 BulletIgnore 系列实现（自原始 Windows/MetaMod 原型 BulletIgnoreTestMM 起）对 CS2 原生 `FireBullet` 路径的逆向结论与设计依据，说明"为什么必须物理删除命中项，而不是修改标志位"。结构偏移与签名核对见[原生兼容性说明](NATIVE-COMPATIBILITY.md)，实现来源见 [PROVENANCE.md](PROVENANCE.md)。

## 问题

子弹在穿透前方人类玩家后再命中其后方的僵尸时，引擎仍按"人体材质"为中间段计算穿透衰减，导致后方目标受到的伤害下降。要让子弹表现得"从未命中该玩家"，需要在穿透与伤害计算之前改写命中链，而不是在伤害端做倍率补偿。

## 命中链的数据结构

`FireBullet` 在构建完命中链后，trace 对象上持有三组平行数据（偏移详见[原生兼容性说明](NATIVE-COMPATIBILITY.md)）：

- **表面数组**：每个表面项记录被命中实体的句柄（`0x2C`）与一个跳过标志；表面项可回查实体类名与队伍。
- **命中元素数组**：每个元素记录区段的起始表面、结束表面（`0x7FFF` 为无效哨兵）与一个标志字节。
- 命中数与容量：容量存在上限，且数量上限参与后续遍历。

命中链随后被三个消费方依次处理：命中过滤循环、逐元素的阻挡/衰减判定，以及下游的伤害循环。设计介入点时必须同时满足这三个消费方，这决定了下文的核心结论。

## 为什么不能只改标志位

原始原型依次尝试过三种"轻量"方案，均无法同时满足过滤循环与伤害循环：

1. **把被忽略元素的标志位清零**：过滤循环将 bit0 == 0 理解为"可穿透/衰减"，但下游伤害循环把 bit0 == 0 理解为"此处无伤害"并停止处理——两个循环对同一位的语义相反。清零后子弹确实不再在人体上衰减，但也不会继续向后处理。
2. **把被忽略元素的标志位置一**：过滤循环将 bit0 == 1 理解为"阻挡"，置位等于把人体变成一堵墙，遍历在此截断，数组被截短。
3. **在阻挡判定处返回"不衰减"**：能跳过单次衰减计算，但元素仍留在伤害循环里，后续处理依旧认为中段存在人体。

结论：唯一能让过滤循环与伤害循环同时表现得"该表面不存在"的方法，是在过滤循环运行之前把对应命中元素**从数组中物理删除**，并把剩余元素紧凑排列。这就是"命中链稳定压缩"。

## 压缩与区段修正

压缩采用双指针原地遍历：读指针扫描原始数组，判定为需要忽略的元素直接跳过，其余元素写回写指针位置，最后提交新命中数。

判定顺序上，先把表面项的实体句柄解析为实体（通用句柄→实体查找表），再检查 Pawn 类名与 CT 队伍；任一步判定失败时该命中项**原样保留**，保证托管侧判定异常不会中断压缩计数的提交，子弹路径按原生行为继续。

区段修正与压缩配合：若某个保留元素的区段起始于被忽略表面（子弹先穿过人体再命中真实目标），把其起始表面坍缩为真实的结束表面，使后续穿透按真实材质而非人体材质计算，即 README 所述"修正后续命中段的起始表面"。

## 只处理子弹路径

过滤、阻挡判定、输出构建等被挂钩位置同时服务于其他 trace 上下文（移动、贴地检查、跟随实体模型等）。在这些上下文里改写数据会破坏非子弹的 trace 结果。原始 Windows 原型为此用栈回溯校验调用链确实位于 `FireBullet` 地址区间内，非子弹上下文一律直通原函数；当前 Linux 实现改为直接挂钩 `FireBullet` 专用命中过滤辅助位置（BuildOutput 后续，`r15` 上下文），从挂钩点选择上把介入范围限定在子弹路径（见[原生兼容性说明](NATIVE-COMPATIBILITY.md)）。

## 来自原始原型的其他经验

以下工程约束在原型阶段由崩溃与回归换得，Linux 移植以不同形式继承（见 PROVENANCE.md 的"保留的行为"）：

- 所有偏移、签名走 gamedata/签名配置而非硬编码，游戏更新后无需重编译即可核对替换。
- 对命中数与数组基址做边界与合理性检查，偏移失配时放弃本次处理而不是遍历野内存。
- 跨地图切换窗口期暂停处理，避免访问旧地址布局。
- 射手队伍从过滤钩子的入参读取，而不是从更早的调用点捕获——后者在部分版本上产生访问违例。
- 输出构建阶段的表面跳过标志会波及被忽略目标身后的敌方表面，需要显式清理，否则整段命中被丢弃；这是"只过滤目标、不碰敌方命中"这一约束的来源之一。
